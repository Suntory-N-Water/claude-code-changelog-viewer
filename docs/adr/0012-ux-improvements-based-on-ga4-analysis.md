# ADR 0012: GA4分析結果に基づくUX改善施策の方針

## Status

Proposed

## Context

Claude Code Changelog Viewer(以下、本サービス)は、Claude Codeの更新履歴を閲覧するためのサービスである。
2026年3月27日〜4月26日の30日間のGA4データを初めて本格分析し、ユーザー行動の実態を把握した。

### サービス現状

- 総ユーザー: 353人、セッション: 828回、PV: 2,452
- デバイス: PC 91% / モバイル 9%
- 流入: Direct 44%, Organic Search 41%, Referral 10%
- 地域: 日本 85%
- 主要リファラー: はてなブックマーク(45セッション)

### 解決したい課題

- トップページのスクロール率が19%(262人来訪、スクロールは51人のみ)
- 古いchangelogページの直帰率が高い(v2.1.63: 77%, v2.1.69: 60%)
- `/docs` がリピーター専用ページになっており新規ユーザーへの導線がない(22人で224PV)
- 通知登録フォームの完了イベントが未計測のためCVRが不明(form_start: 23回)
- Microsoft Teams経由の流入(32セッション)の性質が不明

### 検討した選択肢

各課題に対して、以下の対応方針を検討した。

#### トップページのスクロール率改善

| 選択肢 | 概要 |
|---|---|
| A. ファーストビューに価値説明を追加 | 「Claude Codeの更新履歴を一覧で確認できるサービス」などのキャッチコピーを設置 |
| B. ヒーローセクションのレイアウト刷新 | 視覚的に引きつけるデザインに変更 |
| C. 現状維持 | 対応しない |

#### 古いchangelogページの直帰率改善

| 選択肢 | 概要 |
|---|---|
| A. 最新版へのバナー追加 | 各changelogページ上部に「最新版はこちら」バナーを表示 |
| B. 関連バージョンへのナビゲーション追加 | 前後バージョンへのリンクを追加 |
| C. 現状維持 | 対応しない |

#### `/docs` への導線強化

| 選択肢 | 概要 |
|---|---|
| A. changelogページから `/docs` へリンク追加 | 各changelogページに関連ドキュメントへのリンクを設置 |
| B. グローバルナビに `/docs` を追加 | ヘッダーに常時表示 |
| C. 現状維持 | 対応しない |

#### 通知登録の計測

| 選択肢 | 概要 |
|---|---|
| A. 完了イベント追加(gtag) | フォーム送信成功後に `notify_signup` イベントを送信 |
| B. GA4のフォームエンゲージメント自動計測に委任 | 追加実装なし |
| C. 現状維持 | 計測しない |

#### Teams流入の扱い

| 選択肢 | 概要 |
|---|---|
| A. 除外フィルタを設定 | GA4のフィルタで `statics.teams.cdn.office.net` を除外 |
| B. 追加調査してから判断 | 実際の人間のアクセスかボットかを確認してから判断 |
| C. 現状維持 | 対応しない |

## Decision

**GA4分析結果に基づき、即時着手する施策・検討継続する施策・追加調査が必要な施策を明確に区分する。**

### 1. 採用(即時着手)

**古いchangelogページへ「最新版へ」バナー追加(選択肢A)**

v2.1.63(直帰率77%)、v2.1.69(60%)など古いバージョンページは検索経由で着地後に離脱するパターンが顕著。最小限の実装で回遊率向上が見込める。

**changelogページから `/docs` へのリンク強化(選択肢A)**

`/docs` は1人あたり10PV以上閲覧されるリピーター向け高品質コンテンツだが、新規ユーザーの流入が少ない。changelogとの関連付けで認知を広げる。

### 2. 検討中(設計精査が必要)

**トップページのファーストビュー改善**

スクロール率19%は低いが、ファーストビューの変更はサービス全体の印象に影響する。ADR 0011(UIポリッシュ方針)との整合性を確認した上で設計を進める。

**通知登録完了イベントの計測追加**

`form_start` 23回に対して完了イベントが0件のため現在のCVRが不明。以下の実装を予定。

```js
// /notify のフォーム送信成功コールバック内に追加
gtag('event', 'notify_signup', {
  event_category: 'engagement',
});
```

### 3. 追加調査が必要

**Microsoft Teams流入(32セッション)の扱い**

`statics.teams.cdn.office.net` 経由のアクセスについて、Teamsのリンクプレビューボットによる自動フェッチか、実際の人間のアクセスかを判別できていない。社内はSlackを使用しているため、社外の誰かがTeamsでURLを共有している可能性がある。除外フィルタ設定の前に実態を確認する。

### 4. 課題なしと判断

**v2.1.96の滞在時間(14秒)**

他のchangelogページが75〜145秒の滞在時間に対し異常値に見えたが、v2.1.96の更新内容が1件のみのため仕様通りの挙動。対応不要。

## Consequences

### Positive

- 古いchangelogページに最新版バナーを追加することで回遊率の向上が期待できる
- `/docs` への導線強化でリピーター転換率の向上が見込める
- 通知登録の完了イベント計測により、今後の施策効果測定が可能になる

### Negative

- トップページ改修は設計コストが高い
  - → ADR 0011のUIポリッシュ方針と合わせて設計し、1回の改修で対応する

### Risks

- Teams流入を安易に除外すると、実際のユーザーのアクセスも除外してしまう可能性がある
  - → 実態確認(User-Agentの調査等)を先に行う

## 決めていないこと

| 項目 | 決めない理由 | いつ決めるか |
|---|---|---|
| トップページの具体的なデザイン | UIポリッシュ方針との整合が必要 | ADR 0011レビュー後 |
| Teams流入の除外フィルタ設定 | 実際の人間のアクセスかどうか未確認 | User-Agent調査後 |
| 通知登録のCVR目標値 | 現在のCVRが不明なためベースライン設定不可 | 計測開始から1ヶ月後 |
